## V1.1 能力落地 + 并发写库两个隐蔽 bug（当天下午）

- 新增模块：`tags.rs`（标签/星标/收藏）、`similar.rs`（64 位 dHash + 汉明距离并查集）、`livepair.rs`（实况照片一对一配对）、`watch.rs`（轮询源根目录 mtime → 排队增量扫描）；`archive.rs` 增加 `mode=copy|move` 与按批撤销；schema 升到 v4（列级幂等迁移）。
- **并发写库坑一：`attempt to write a readonly database`（无扩展码）**
  - 只在「扫描任务线程 + API/监控线程并发短连接」时随机出现，且一次坏掉整批（8/8 全失败）。
  - 根因：WAL 库在**最后一条连接关闭时删除 `-wal`/`-shm`**，与另一线程同时 `Connection::open` 形成竞态，新连接退化为只读。
  - 修法：`db.rs` 用 `OnceLock<Mutex<HashMap<PathBuf, Connection>>>` 保留一条**进程级常驻连接**（永不关闭、不持事务）。两个关键点：① 必须在 `migrate` 之后创建（空库时 WAL 头还没写）；② 建完必须真读一次（`SELECT COUNT(*) FROM sqlite_master`），否则 SQLite 不把它计入 WAL 共享内存，挡不住删除。
  - 验证：写了最小复现 `examples/conc_db.rs`（无 anchor：A 失败 60 次 / B 失败 3 次；加 anchor：均为 0），确认后删除该示例。
- **并发写库坑二：`database is locked`（扩展码 517 = SQLITE_BUSY_SNAPSHOT）**
  - 扫描用 `BEGIN`（延迟事务）先读后写，期间监控线程提交了一条日志写入 → 事务快照失效，之后**所有**写入立刻失败；`busy_timeout=8000` 对“读升级写”的死锁完全不生效（所以不是等 8 秒才失败，而是 0ms）。
  - 修法：写事务一律走 `db::begin_write()`（`BEGIN IMMEDIATE` + 5 次退避重试，150ms×n）；扫描内单文件遇 busy 时回滚重开事务重试 3 次（单文件是一致性单位）；扫描提交节奏从「每 200 文件」改为「每 50 文件或每 700ms」，把他人的等锁上限压到 1 秒内。
  - 诊断技巧：`rusqlite::Error::SqliteFailure(f, _)` 的 `f.extended_code` 一定要打出来，只打 `to_string()` 只能看到 "database is locked"，区分不了 BUSY / BUSY_SNAPSHOT / READONLY。`scan.rs` 已加 `sqlite_err()`。
- 顺手优化：`PRAGMA journal_mode=WAL` 原来每次 `open` 都执行，属于多余操作（模式持久化在库头），改成只在非 WAL 时切换。
- 测试：`test/v11.js` 37 项断言全绿（移动后源消失/索引改路径/撤销还原、相似组最大距离 4、实况双向配对、监控 30s 内触发）；新增 `test/ui/ui-v11.js` 23 项界面断言（相似页分组、标签/星标筛选、详情加标签、偏移弹窗、向导移动模式、撤销按钮消失与副本清理、监控设置回显、非媒体视图隐藏批量条）。夹具在 `test/fixtures/v11/`，由 `examples/gen_variants.rs` 生成。

## V1.3（竖屏水印定位、覆盖原图、启动与网络健壮性）

- **“竖屏照片水印位置不对”的结论**：拿真实素材验过一轮——JPEG 的 EXIF 方向 1/3/5/6/7/8 全部换算出正确的显示宽高，iPhone 竖拍 HEIC（3024×4032）也正确（libheif 已应用 irot，`heic_exif_segment` 再把 Orientation 归 1）。所以不是方向换算 bug，而是**照片本身没有方向标记**（社交软件转发会剥掉 EXIF）时，用户无法纠正。对策：水印 Config 加 `rotate_image`（0/90/180/270），预览卡片上显示「EXIF 方向 6 / 无方向标记」让用户自己判断。
- 水印加 `mode: copy|overwrite`：覆盖模式先备份到 `<数据目录>\backups\wm-<jobId>\`（拷失败就放弃），只允许 jpg/png/webp/tiff 且格式不能变，写临时文件再 `rename`，完成后更新 `media_files.size_bytes/mtime_ms` 并清 `media_previews`（否则界面还显示打水印前的缩略图）。HEIC 覆盖会明确报错（没有 HEVC 编码器）。
- **启动方式**：release 加 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` + `AttachConsole(ATTACH_PARENT_PROCESS)`。验证过 GUI 子系统下 `> server.log` 仍能拿到日志（句柄继承），PE Subsystem=2。致命错误用 `MessageBoxW` 弹窗，避免“双击没反应”。
- **“Failed to fetch”**：`api::handle` 包 `catch_unwind`（之前任一 handler panic 会永久打死一个 HTTP 工作线程，12 个打完服务就哑了），panic 文本入 response + `logs/panic.log`；前端 `api()` 对 GET 重试一次并换成中文提示。
- **“接口不存在”**：静态资源加 `Cache-Control: no-store, must-revalidate`——升级 exe 后浏览器还在用旧 app.js 是最可能的元凶；另外 `/api/file/:id` 增加“按条目 id 取主文件”的兜底，`/api/file` 无 id 时给 400。
- **水印编辑器底部被裁**：`.wm-layout` 补 `grid-template-rows: minmax(0,1fr)` + `overflow:hidden`，`.wm-runbar` 设 `flex:0 0 auto`。之前 grid 的隐式行使整列高度超出视口，底栏被窗口裁掉。
