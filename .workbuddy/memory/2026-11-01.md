## V1.6.0 收尾与相册密码保护（任务全部完成）

- **根因定位（albumpw 解密失败）**：Rust 加密与浏览器解密都没问题——盐一致、PBKDF2 密钥与 Node 完全一致（`crypto.pbkdf2Sync('test-pass-123', salt, 200000, 32, 'sha256')` 逐字节吻合）。真正的 bug 在 **Node e2e 测试**：Node 的 `createDecipheriv('aes-256-gcm')` 必须把密文末尾 16 字节拆出来 `setAuthTag()`，而 Rust `aes-gcm` 的 `encrypt` 输出是 `密文‖标签`、浏览器 Web Crypto 原生就吃这个格式。实验：不拆标签解密必失败，拆了必成功。
- 修 `test/albumpw.js`：解密前 `const tag=ct.slice(ct.length-16); const body=ct.slice(0,ct.length-16); decipher.setAuthTag(tag)`。**浏览器侧代码无需任何修改**。
- 清理调试痕迹：删 `album.rs` 里 `derive_key` 的 `eprintln!("PVMKEY ...")` 和 `dump_fixed_ciphertext` 调试测试。
- **回归全绿**：`cargo test --release` 93/93（含 3 个 crypto 单测：AES 往返、错密码密钥不同、PBKDF2 对标准向量）；e2e `test/albumpw.js` 13/13、`test/imgops.js` 32/32、`test/albumtheme.js` 37/37。零警告构建。

- 相册密码方案回顾：AES-256-GCM 内嵌加密（每图大图/缩略图各 12 字节随机 nonce，JSON 字段 `nonce`/`nonceT`），PBKDF2-HMAC-SHA256 20 万次迭代派生密钥，盐内嵌 index.html，浏览器 Web Crypto 本地解密，密码不落盘。曾尝试 zip 层 AES 但 `zip 9.x` 的 `aes-crypto` 特性依赖 sha1 ^0.11（仅 prerelease）无法解析而放弃。
